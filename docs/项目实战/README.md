# 项目实战专题：把"做过项目"变成"能拿来面试"

项目不是简历上的技术词堆叠，而是面试官判断你工程能力的证据。一个能讲清楚的项目，至少要具备四件事：

1. 有明确业务场景，而不是"为了用技术而做技术"。
2. 有可解释的架构设计，而不是照着教程搭一遍。
3. 有真实难点和取舍，而不是只完成 CRUD。
4. 有可验证结果和追问准备，而不是写完就结束。

本专题按"**先算账、再设计、再验证**"组织。每篇都从容量和延迟估算开始，每个设计决策都给替代方案，最后给出能自己跑的验证方法。

## 大模型项目（主线）

这五篇服务 AI 应用研发、大模型应用、智能体开发方向。选哪个，看你的目标 JD 里出现的是什么词。

| 项目 | 讲什么 | 一句话价值 |
| --- | --- | --- |
| [Agent 工具调用平台](./Agent工具调用平台拆解.md) | 上下文膨胀、参数校验、权限分级、循环防护 | 可控比自主更值钱 |
| [AI 应用评测平台](./AI应用评测平台拆解.md) | 测试集资产化、并发执行、回归比对、badcase 回流 | 最容易被跳过，也最能把人区分开 |
| [RAG 项目从 0 到 1](./RAG项目从0到1.md) | 延迟与 token 预算、混合检索、权限下推、评测集 | 入场券项目，必须做出评测才加分 |
| [结构化信息抽取系统](./结构化信息抽取系统拆解.md) | Schema 约束、校验重试、字段级置信度、人工闭环 | 最贴近业务，金融国企岗最认 |
| [文档智能解析系统](./文档智能解析系统拆解.md) | 分级路由、版面分析、表格结构、阅读顺序 | RAG 的地基，多数人没打好 |

先看 [AI 应用研发作品集项目清单](./AI应用研发作品集项目清单.md)，里面有一组真实 JD 的关键词统计，告诉你哪些是门槛项、哪些是加分项。

## 传统后端项目（副线）

如果目标 JD 里出现的是 Spring、MySQL、Redis、消息队列、高并发，走这条路。见 [传统后端项目](./传统后端项目/README.md)，含秒杀、短链、IM、API 网关、权限系统五篇拆解。

两条路可以并行：**一个主项目加一个辅项目，比两个都半吊子强**。

## 五篇大模型项目各配数据图

| 项目 | 图说明什么 |
| --- | --- |
| Agent | 上下文随轮数线性膨胀，20 轮超 16K 窗口；单轮 3.6 秒里模型生成占一半；压缩与不压缩差出一倍 |
| 评测平台 | 一次回归评测串行要一个半小时；裁判一致率随校准量变化；四个版本在五类指标上的回归矩阵 |
| RAG | 一次问答 2.3 秒，2 秒在等模型；上下文里检索片段占六成；三种切分策略的召回与引用准确率 |
| 结构化抽取 | 阈值每降一档自动化上去漏错也上去；单份 2.2 秒里模型占九成；自动化率与漏错率的权衡曲线 |
| 文档解析 | 一页 PDF 6.6 秒，100 页 11 分钟；三种解析深度的还原质量差距 |

除数据图外，每篇还配**结构示意图**（架构图、流程图、时序图）。数据图回答"数字是什么关系"，示意图回答"模块怎么连"，两者不能互相替代。

| 示意图 | 看什么 |
| --- | --- |
| [RAG 架构图](./images/diagram-rag-arch.svg) | 四层结构，评测库常被漏掉 |

这些数字都是**按正文给出的假设推导的工程量级**，不是实测值。每张图的口径说明里写清了假设和算式，来源登记在两个文件里：

- [`docs/_data/llm-project-metrics.json`](../_data/llm-project-metrics.json) —— 大模型项目
- [`docs/_data/project-metrics.json`](../_data/project-metrics.json) —— 传统后端项目

落到自己机器上必须实测，实测和估算不一致时以实测为准。图表由脚本生成，改数据后重跑即可复现：

```bash
python tools/build_llm_project_charts.py    # 大模型项目图表 12 张
python tools/build_project_charts.py        # 传统后端项目图表 15 张
python tools/build_project_diagrams.py      # 结构示意图 9 张
```

## 项目面试评分标准

| 维度 | 低分表现 | 高分表现 |
| --- | --- | --- |
| 真实性 | 只能说用了什么技术 | 能讲清自己负责的模块、代码细节和排查过程 |
| 复杂度 | 只有增删改查 | 有并发、性能、一致性、权限、安全、可观测等问题 |
| 取舍 | "网上都这么做" | 能解释为什么选这个方案，替代方案是什么 |
| 结果 | 没有验证 | 有压测、日志、指标、测试集、错误案例 |
| 表达 | 技术词堆叠 | 背景、方案、难点、结果、反思结构清楚 |
