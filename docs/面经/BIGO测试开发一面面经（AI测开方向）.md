## 基本情况

- 公司/岗位：BIGO，测试开发（秋招一面）
- 轮次：一面（技术面）
- 结果：一面通过，约 9.15 二面
- 特点：大量围绕"用 AI 做测试"的项目追问，是 AI 与测开结合的典型样本

## 面试过程

1. 自我介绍
2. 开发和测开的区别是什么
3. 测开对比测试的优势是什么
4. 讲解滴滴实习工作：三方商家接入后，一个拼车订单从产生到司机接单、完单中间有哪些链路
5. 场景题：乘客侧显示成功发起订单，司机却没有收到去目的地的提示，给出排查思路
6. 如果排查到问题并通知司机去接单，但司机不去，如何安抚乘客
7. 对于这部分工作，如何搭建接口自动化框架、断言怎么设置；如果有异步数据传递、接口延迟，断言是直接判失败还是继续等待，等待时间一般多久
8. 跑一轮自动化耗时多少
9. 讲一下 test_case 生成 skill 的实现细节
10. 如果产品 PRD 的描述非常模糊，你的 skill 生成效果还能保持很好吗
11. 针对 SDK 升级场景的需求，如何改进你的 skill，确保生成 case 可用（面试官针对回答连续追问了几个点）
12. 讲解百度实习工作：你编写的 UI 自动化 skill 的架构是什么，和传统 UI 自动化的区别在哪里
13. 用的什么模型，讲解 token 消耗、围栏设计、性价比、执行时间等
14. 场景题：如果一个 h5 上有一个广告滚动播放位，你如何修改这个 skill 测试广告位设置符合预期
15. 用例设计：针对微信 1v1 视频电话场景设计测试用例
16. 做过性能测试吗，性能测试常见指标有哪些
17. 代码手撕：一道 medium，力扣原题 86. 分隔链表
18. 反问：一面后多久出结果，部门业务是什么

## 复盘建议

- 这轮的核心看点是"AI 生成的测试用例怎么保证可用"。第 9-11 问是一条完整追问链：实现细节、PRD 模糊时怎么办、需求变化时怎么改进。准备这类项目时要能讲清输入（PRD 格式约束）、输出（case 结构）、校验（编译/静态检查/人工抽检）、迭代（bad case 回流）。
- "PRD 描述模糊"是必问的坑，标准思路是加结构化模板和澄清机制，而不是硬猜。相关做法可参考[项目实战专题](../项目实战/README.md)里评测平台的验证方法。
- 业务链路题（拼车订单全链路）要按角色和状态机梳理：乘客、商家、司机三方各有哪些状态，事件怎么驱动流转，画出来再讲。
- 手撕是力扣 medium 原题，测开岗代码要求通常不高于开发岗，但必须一次写对。反转、分隔、合并这类链表操作是高频题库。
