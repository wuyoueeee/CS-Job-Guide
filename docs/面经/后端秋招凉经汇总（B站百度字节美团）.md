## bilibili（服务端开发工程师）

先做自我介绍，然后围绕论文和 Agent 连续追问：

1. 论文什么时候开始做的，现在什么状态，具体解决什么问题
2. 方法具体怎么做，为什么可以说和 Agent 有关系
3. 如果换一个能力比较弱的大模型，这套方法还能工作吗
4. 大模型生成的算法不合法怎么办，会修复吗
5. 怎么保证换模型以后整个 Workflow 还能运行
6. 介绍你接触 AI/大模型以来的发展过程
7. 最近有没有关注 Agent 方向的论文或技术

接着转后端基础：

8. 为什么 Go 适合高并发
9. Go 里面有没有遇到并发安全问题，怎么处理
10. sync.Map 的底层实现
11. 操作系统的内存管理，常见内存分配策略，怎么判断一个内存分配算法好不好，如果让你实现空闲内存管理你会怎么做
12. 实习期间主要做了什么，做过什么性能优化，为什么当时不通过加索引解决
13. EXPLAIN 看过吗，查询有没有走索引；MySQL 有哪些索引，索引是不是越多越好，设计索引的原则；除了 B+ 树还有什么索引结构，Hash 和 B+ 树区别；为什么不用普通二叉搜索树
14. 如果让你设计短链接系统，短链接和长链接应该是什么关系，怎么进一步缩短 URL
15. 手撕链表反转，并追问"刚才这个代码有什么问题"

## 百度（北京后端）

纯八股，分享者自评基础不扎实。题目包括：平时刷题和做项目用什么语言、为什么项目更倾向 Go；make 和 new 区别；数组和切片区别，slice 底层结构，len 和 cap，append 扩容机制；Goroutine 为什么轻量，GMP 调度，上下文切换；进程线程协程区别；虚拟内存、页表转换、缺页中断；生产者消费者；读写锁；HTTP/HTTPS 区别、TLS 握手流程、数字证书作用；DNS 的 A 记录和 CNAME；TCP 一端断网后另一端继续发数据会怎样、超时重传、滑动窗口、TIME_WAIT 作用；Redis 数据结构、为什么快、Lua 原子性、缓存穿透、事务 MULTI/EXEC 是否支持回滚、分布式锁 SETNX EX 为什么用 Lua 释放；算法题：小于 n 的最大数。

## 字节飞书/飞书云文档后端（一面 45 分钟）

先自我介绍，再从项目问起，穿插八股，最后一道算法一道场景：

- 算法：缺失的第一个正数
- 场景题：几十 TB 的用户 id 数据，内存 4G，如何找出频率最高的 top10 id（分享者答哈希分堆 + top10 小根堆过滤，面试官花了好一会儿校正补充，集中在哈希函数怎么设计、额外空间留多少、过滤前是不是要先统计）
- 项目和八股：竞赛里 Redis Lua 的作用和原子性、失败是否回退；实习时 SQL 优化怎么做、索引、为什么用 B+ 树、索引是否越多越好；TCP 三四握手、URL 到渲染全过程、DNS 解析和缓存；HTTPS 怎么实现安全、数字证书（被问"如果我伪造说我是百度的呢"答不上来）；线上告警排查（火焰图、top、load、内存满了怎么办）

## 字节火山引擎生态 Agent 后端（一面 1 小时 45 分）

5. 为什么用 Redis Stream 而不是 Kafka、RocketMQ，数据怎么落库
6. Room 是真实实体吗，WebSocket 断线怎么恢复，怎么保证重连后进原来的房间
7. Redis 数据怎么组织，为什么参与用户用 Set、排行榜用 ZSet，ZSet 底层结构

## 字节字节云 AI 算力基础设施后端（二面后挂）

一面八股覆盖：进程线程区别、共享与私有资源、协程、GMP、用户态内核态、虚拟内存、缺页中断、OSI 七层、TCP 可靠传输、Cookie/Session、RESTful、MySQL 索引、LangGraph、安全系统核心模块、大模型与传统算法结合、Agent 能否封装成 Skill、K8s、Agent Sandbox、DeepSeek Harness。手撕：带统一 TTL 的 LRU Cache（优先淘汰过期 KV，无过期则淘汰 LRU）。

二面几乎全是一个竞拍项目的并发与一致性追问：

1. 高并发下"读取当前值、判断、写入"不是原子操作，怎么避免竞态；两个请求同时基于旧数据判断，怎么防止后写入的低值覆盖先写入的高值
2. Redis Lua 怎么实现判断+更新的原子操作，做了哪些校验和状态转换
3. Redis 操作成功后什么时候写 MySQL；异步落库怎么保证最终一定写入；消费者挂掉重启怎么不丢消息；重复消费怎么保证幂等
4. 最终结算以 Redis 还是 MySQL 为准，两者有延迟怎么保证一致；结算与最后一次并发操作同时发生怎么拿到最终状态；怎么通过状态机阻止结算后的新请求
5. Redis 异常、数据丢失怎么办；为什么用 Redis + Lua 而不是分布式锁 + MySQL；核心目的是抗并发、低延迟还是原子性；为什么把实时热路径和 MySQL 写路径解耦
6. 幂等键怎么设计、在哪里生成、怎么判断请求是否处理过、在哪个阶段写入、怎么区分成功/失败/处理中、失败结果要不要缓存、放 Lua 里还是 Lua 返回后写；Lua 已执行但幂等键没写入时客户端重试怎么办；SETNX 能不能直接解决幂等
7. AI Coding 相关：平时怎么用，和传统开发流程的区别，用过哪些 Skill，Skill 怎么工作，怎么提供上下文，哪些工作交给 Agent，任务拆分是人定义还是 Agent 定义，用过哪些 AI Coding 工具，能不能现场演示一次完整流程
8. 手撕：三个线程循环打印 123123123（flag 状态变量、虚假唤醒、为什么条件判断要写在 while 里）；设计支持 get/set 的 LRU Cache，并追问答 TTL 过期、惰性删除还是定时清理、get/set 是否刷新过期时间、并发一致性等十几个问题

## 复盘建议

- 这份合集的挂点高度一致：项目讲不深、AI 工具只会用不会讲、八股有盲区。B 站那轮从论文追问到 Agent 泛化性，火山那轮从 Redis Lua 追问到幂等设计，都是同一个模式——抓着你最亮眼的部分一层层往下剥。
- "AI Coding 怎么用"已经成为独立考点（美团、字节两轮都专门追问）。准备时把 Prompt 设计思路、人机分工、Skill 工作原理各写一版答案，这恰好是[用 AI 求职全流程](../用AI求职全流程.md)里反复强调的人工校验点。
- 场景题（4G 内存找 top10、带 TTL 的 LRU）没有巧思，考的是把问题拆成"统计、过滤、维护"的链路闭环，以及每个环节的空间/时间账。相关训练见[项目实战专题](../项目实战/README.md)的容量估算方法。
- 智驾新程半小时只问项目就结束，说明不同公司风格差异极大，投递前按公司类型（大厂/车企/中小厂）分别准备两套项目讲述版本。
